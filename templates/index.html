% Victoires

🏆 Pourcentage de Victoires
Victoires : On additionne toutes les victoires du joueur dans toutes ses sessions.

Parties : On compte toutes les parties jouées dans tous les groupes où le joueur a participé. Si une session a 4 joueurs qui ont gagné 10, 8, 6 et 4 parties chacun, cela fait 28 parties au total pour cette session.

Joueurs avec 0 victoires : Tous les joueurs présents dans une session sont comptabilisés, même ceux qui n'ont gagné aucune partie.

Pourcentage : (Victoires ÷ Parties) × 100

Exemple : Si un joueur a 50 victoires sur 100 parties, son pourcentage est de 50%.

ELO session

🏆 Classement ELO session
Qu'est-ce que l'ELO ?
Un système de classement qui évalue le niveau de chaque joueur. Plus le score ELO est élevé, meilleur est le joueur.
En savoir plus sur Wikipedia

Calcul
• Tous les joueurs commencent à 1500 points
• Les joueurs sont classés selon leur nombre de victoires dans la session
• Les confrontations sont évaluées entre toutes les paires de joueurs
• Les variations d'une session sont appliquées en batch à la fin de la session
• Battre un joueur plus fort fait gagner plus de points

Différence avec ELO legacy
ELO legacy mettait à jour les ratings séquentiellement à l'intérieur d'une session : l'ordre des paires pouvait influencer le résultat final. Le calcul batch est plus stable et déterministe.

Facteur K = 32

ELO match

⚔️ Classement ELO match
ELO recalculé match par match dans l'ordre global (dates de session, puis ordre des matchs dans chaque session). Pour chaque match, les joueurs sont classés par nombre de kills ; les paires et le batch suivent la même règle que l'ELO session.

Une session sans score par match n'alimente pas ce calcul : le joueur reste à 1500 jusqu'à ses premiers matchs comptés.

Facteur K = 32, appliqué après chaque match.

👥 Classement par Groupe
Pour chaque joueur du groupe sélectionné, on additionne ses scores de chaque session (victoires du jour) de ce groupe.

Les joueurs sont classés du plus haut total au plus bas. Lorsque des filtres (ex. dates) sont appliqués, le classement est recalculé sur les sessions visibles.

Exemple : Si un joueur a eu 50, 75 et 60 victoires dans trois sessions du groupe, son score groupe est 50+75+60 = 185.

🔧 Correction des Données
Algorithme de correction des incohérences

Les données brutes peuvent contenir des incohérences entre TodayWins et TotalWins. Un algorithme corrige automatiquement ces erreurs. Parfois, Eric a dû éditer manuellement certaines entrées pour rattraper des plantages du jeu... qui plante parfois malgré ses améliorations (comme le stockage des stats dans Google Sheets). 😅

Principe de correction :
Pour chaque groupe de joueurs, les sessions sont traitées dans l'ordre chronologique (de la plus ancienne à la plus récente).

Pour chaque session et chaque joueur :
• On récupère le TotalWins actuel et le TotalWins de la session précédente
• On calcule le TodayWins attendu : TodayWins = TotalWins_actuel - TotalWins_précédent
• Si le TodayWins enregistré ≠ TodayWins attendu ET TodayWins attendu ≥ 0, on corrige TodayWins
• On met à jour le TotalWins précédent pour la prochaine session

Normalisation des joueurs :
Tous les joueurs présents dans les statistiques détaillées (today/total) sont automatiquement inclus dans todayWin et totalWin, même s'ils ont 0 victoires.

Format des données :
Les données utilisent le format todayWin[player] et totalWin[player] pour stocker les statistiques de chaque joueur.

Filtrage :
• Sessions passant minuit : si une session se termine après minuit, seule la session du jour suivant (00h-05h) est conservée
• Joueurs invalides : AIJIMMY, P1, P2, A, BB, etc. sont ignorés

Modes de jeu (v4) :
Depuis avril 2026, Eric a ajouté un champ mode dans les stats v4. Les anciennes sessions sans mode sont traitées comme Head Hunters. Les cumuls sont calculés séparément par mode.

Données corrigées avec amour par l'algo — quand Eric ne plante pas le jeu (ni la Google Sheet).
